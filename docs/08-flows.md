# 08 — User Flows

*Два контекста: городская аренда (часы) и горный/суточный маршрут. Флоу отличаются в trust-layer и в передаче ключей.*

---

## A. Host Onboarding Flow

```
Регистрация
  → загрузка профиля (ФИО, телефон, фото)
  → добавление авто: фото (11 ракурсов), документы (4 типа), описание
  → верификация платформой: [CTO: кто аппрувит — вручную или автомат?]
  → установка цены + доступности
  → опционально: оплата "выдвижение в топ" [CTO: это отдельный шаг при онбординге или потом?]
  → авто появляется в листинге
```

**Ключевой вопрос хоста:** "Когда я получу деньги?" — ответ должен быть в онбординге явно.

---

## B. Driver Verification Flow

```
Регистрация (телефон + email)
  → загрузка ВУ + паспорта (фото)
  → selfie-match
  → [Joldo-check если КР] / [документы иностранца — отдельный путь]
  → аппрув: [CTO: SLA? 24ч? Мгновенно для базового уровня?]
  → профиль активен, можно бронировать
```

---

## C. Search & Booking Flow (городская аренда)

```
Поиск: дата + время + локация
  → листинг: сортировка по [рейтинг / цена / расстояние / топ-размещение]
  → карточка авто: фото, верификационный бейдж, отзывы, цена
  → выбор слота
  → checkout:
      → pre-auth на карте [CTO: сумма = аренда + депозит? Или только аренда?]
      → договор — электронная подпись
      → хост получает уведомление (Telegram / push)
  → хост подтверждает бронирование [CTO: есть ли автоподтверждение?]
  → статус: CONFIRMED
```

**[CTO: если нет эскроу в классическом смысле — pre-auth на карте это и есть холдирование. Как вы называете это для хоста и водителя? Важно для UX-копирайта.]**

## D. Key Handoff Flow

### Городская аренда
```
За 30 мин до начала: push-уведомление обеим сторонам
  → координация точки встречи в чате (или зафиксирована заранее)
  → встреча:
      → фото-осмотр: 4 стороны + салон, оба подтверждают в приложении
      → фиксация состояния: царапины, уровень топлива
      → водитель получает ключи → нажимает "ключи получены"
      → хост подтверждает → поездка начата, таймер запущен
```

**[CTO: физическая встреча для 2-3 часовой городской аренды — это UX-проблема. Решение: локер-бокс? Заранее договорённое место у хоста? Или мирятся с этим на MVP?]**

### Горный / суточный маршрут
```
Та же механика встречи, но:
  → дополнительный чеклист: запасное колесо, домкрат, трос, аптечка
  → контакты сохраняются оффлайн
  → договор доступен оффлайн
  → точка возврата согласована заранее
```

## E. Trip Flow

```
Поездка активна:
  → таймер и сумма видны в приложении
  → кнопка "SOS / экстренная связь" всегда доступна
  → продление аренды: [CTO: можно продлить в приложении? Или только через хоста?]
  → досрочный возврат: [CTO: пересчёт по факту или только если хост согласен?]
```

**Горные маршруты:**
```
  → оффлайн режим: фото-фиксация инцидентов сохраняется локально
  → синк при появлении сети
```

---

## F. Return & Payment Flow

```
Водитель приезжает в точку возврата
  → фото-осмотр при возврате (аналогично выдаче)
  → хост принимает авто:
      → [нет претензий] → подтверждает возврат
          → депозит размораживается / pre-auth снимается
          → оплата за аренду проходит
          → хост получает [сумма - 15% комиссии]
      → [есть претензия] → фиксируется в приложении
          → [CTO: кто арбитр? Команда CarPal вручную? Есть ли SLA на решение?]
          → депозит удерживается до решения
```

**[CTO: сколько времени хост имеет чтобы заявить претензию после возврата? Если не заявил — автоматическое подтверждение через X часов?]**

---

## G. "Выдвижение в топ" Flow (монетизационный слой)

```
Хост в личном кабинете:
  → раздел "Продвижение"
  → выбор: [CTO: периоды? 7 дней / 30 дней? Фиксированная цена или аукцион?]
  → оплата
  → авто поднимается в поиске с бейджем "Рекомендовано"
  → аналитика: показы / клики / конверсия в бронирование
```

**[CTO: бейдж "топ" виден арендатору явно (как на Airbnb "Superhost") или только ранжирование меняется незаметно?]**

---

## H. Dispute Flow (упрощённый)

```
Открытие спора:
  → водитель или хост нажимают "есть проблема"
  → фото-доказательства загружаются обеими сторонами
  → CarPal-команда рассматривает [SLA: CTO заполняет]
  → решение: депозит полностью / частично / не удерживается
  → уведомление обеим сторонам
```

**[CTO: есть ли порог "мелкий ущерб" ниже которого хост не может открыть спор? Чтобы не флудили по каждой царапине.]**

## Открытые вопросы по флоу (для CTO)

1. Pre-auth = de facto escrow — как это называется пользователям? "Резерв средств"?
2. Автоподтверждение бронирования хостом: да/нет, и через сколько часов таймаут?
3. SLA на верификацию водителя в MVP: 24 ч? Мгновенно для базовой верификации?
4. Продление аренды в городском кейсе: in-app или звонок хосту?
5. Автоматическое подтверждение возврата если хост не заявил претензию через X ч: сколько X?
6. Порог мелкого ущерба который не запускает арбитраж: фиксированная сумма?
